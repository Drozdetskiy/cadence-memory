# Changelog

## v0.3.0 - 2026-05-07

### New Features

- `api-spec` chunker for OpenAPI-style markdown: splits a document into a preamble chunk, one chunk per endpoint (`## GET /v1/foo`), and an optional trailing schemas chunk when the doc has a `## Schemas`, `## Models`, or `## Components` H2; selectable via frontmatter `kind: api-spec` or `discover.kind_rules`.
- Each chunk gains a short body-derived `summary` field, surfaced in `query` output (table column and JSON field); legacy v0.2.0 stores pick up the new column the next time the store is opened (run `cadence-memory reindex` to populate summaries).
- `cadence-memory reindex` enriches each new or changed chunk via Claude with cross-lingual keywords, questions, and alt phrasings, indexed alongside the chunk for better recall; per-chunk cache keyed on content + model so unchanged chunks (and `--no-enrichment` runs) keep prior enrichment for free. Flags: `--no-enrichment`, `--enrichment-model`, `--enrichment-idle-timeout` (default 300s). Config: top-level `enrichment` block with `enabled`, `model`.
- `cadence-memory mentions <chunk_id>` lists outbound references (code paths, HTTP endpoints, CamelCase schema names, markdown doc links) extracted from a chunk's body during reindex.
- `cadence-memory backlinks <target>` finds chunks that mention a given target. Both commands accept `--kind` and `--format table|json`.
- Query results now combine FTS5 BM25 with an identifier-aware ranking boost that lifts chunks matching JIRA, release, acceptance, CamelCase schema, or HTTP endpoint tokens extracted from the query. On by default; disable with `--no-boost`. JSON output exposes per-chunk `score` and `score_boost`.
- `cadence-memory query` expands the user's query through Claude into alternative phrasings, runs FTS5 across all variants, and merges results via reciprocal rank fusion on top of the identifier boost. Per-(query, model) cache in SQLite. Flags: `--no-expand`, `--expansion-model`, `--variants`. Config: `query.expansion` block (`enabled`, `model`, `max_variants`). Falls back to the original query with a stderr warning when the LLM fails or returns FTS5-invalid variants.
- `cadence-memory query` reranks the top-K candidates via Claude and surfaces `score_rerank` per chunk in JSON. Flags: `--no-rerank`, `--rerank-model`, `--rerank-top-k`. Config: `query.rerank` block.

### Also since v0.1.0

- `cadence-memory projects add|list|remove|autodetect` round-trip-edits `config.yaml` (preserving comments) so projects can be managed without hand-editing YAML; `autodetect` walks a root directory to a configurable depth and adds any git repositories it finds.
- `cadence-memory projects add` and `cadence-memory projects autodetect` seed default Python exclude globs (`.venv/`, `__pycache__/`, etc.) for each new project; pass `--no-default-exclude` on `projects add` to skip (autodetect always seeds). The same list is also written as a commented example in the `config.yaml` generated by `cadence-memory init`.
- `cadence-memory discover` caches per-file annotation results keyed on path + content hash so reruns skip unchanged files; disable with `--no-cache`.

## v0.2.0 - 2026-05-06

### Breaking change

- Schema: store теперь индексирует чанки. Существующие store'ы требуют `cadence-memory init` + `reindex`.

### New Features

- Markdown chunker splits each document into chunks at H1/H2 boundaries (code-fence aware), with oversized chunks sub-split by H3 or paragraph blanks; documents without headings produce a single `_preamble` chunk.
- `cadence-memory query` now returns chunks instead of whole documents — table output gains `kind`, `chunk_id`, `heading` columns; json output exposes `chunk_id`, `document_id`, `kind`, `title`, `project`, `heading_path`, `slug`, `snippet`.
- `cadence-memory get <doc_id>#<slug>` prints a single chunk's body; `get <doc_id>` still prints the full document body.

## v0.1.0 - 2026-05-05

First public release. Available via `pip install cadence-memory` and `brew tap Drozdetskiy/cadence && brew install drozdetskiy/cadence/cadence-memory`.

### New Features

- `cadence-memory init` bootstraps a memory store (config.yaml, annotations-config.yaml, .gitignore, ephemeral/, empty SQLite index, `git init`).
- `cadence-memory reindex` rebuilds the SQLite/FTS5 index from `config.yaml` and `annotations-config.yaml`; `--verbose` lists affected document ids.
- `cadence-memory status` is a dry-run reindex that reports what would change without writing.
- `cadence-memory list` / `query` / `get` / `show` browse and full-text-search indexed documents with table or json output.
- `cadence-memory ephemeral add/list/remove/clear` manages per-task notes by copy, symlink, or stdin inline.
- `cadence-memory discover` runs Claude Code over project markdown to populate `annotations-config.yaml`; writes `.proposed` by default, overwrites in place with `--apply` (refuses when the file has uncommitted changes).
- `cadence-memory chat` launches an interactive Claude session with `CADENCE_MEMORY_DIR` exported so the read-only `cadence-memory` skill can query the store.
- Active store is resolved via `--store`, `CADENCE_MEMORY_DIR`, or by walking up from the current directory to find `config.yaml` next to `index.sqlite`.
- Ships two Claude Code skills as embedded defaults: read-only `cadence-memory` (used by `chat`) and write-side `cadence-memory-discover` (used by `discover`).
