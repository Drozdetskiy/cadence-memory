# cadence-memory

Cross-project knowledge layer for Claude Code, designed to complement [cadence](https://github.com/Drozdetskiy/cadence). Stores architecture, patterns, and per-task context as markdown with YAML frontmatter, indexed in SQLite (FTS5), and exposed to Claude through two skills that drive a small CLI.

> **Status:** design stabilized in [`docs/design.md`](docs/design.md); implementation in progress task-by-task under `cdc-tasks/`. The CLI surface below describes the target product.

## Why

When you work across many services in parallel, planning a task that touches several of them needs cross-cutting context: which services exist, how they're wired, where the patterns and ADRs are, what the recent in-flight tickets are. `cadence-memory` is the place that holds this knowledge in a form Claude can query before drafting a plan — a separate git repository per "context" (e.g. one platform, one product), one folder per memory store, no global state.

Design choices, in one breath:
- **Markdown is source of truth, SQLite is a derived index.** Knowledge lives in `.md` files; `index.sqlite` is rebuilt by `cadence-memory reindex`.
- **Two configs.** `config.yaml` lists project paths and exclude globs (hand-edited). `annotations-config.yaml` lists the actual documents and their annotations (machine-generated by `discover`, also editable).
- **Annotations have a strict priority rule.** Frontmatter wins over `annotations-config.yaml` for `kind`/`title`; `tags`/`related` are merged.
- **Skill, not MCP.** Two skills (`cadence-memory` for read-only queries, `cadence-memory-discover` for write-side bootstrap) call the CLI through bash. No MCP runtime, no protocol breakage risk.
- **Streaming Claude executor reused from cadence.** `discover` launches `claude --output-format stream-json --print` with an idle watchdog and process-group cleanup, exactly the way cadence drives Claude.

Full rationale and tradeoffs in [`docs/design.md`](docs/design.md).

## Target CLI

```
cadence-memory init                                 # create config.yaml + annotations-config.yaml + .gitignore + git init
cadence-memory reindex [--verbose]                  # rebuild index from both configs + on-disk .md files
cadence-memory status                               # dry-run: what would change

cadence-memory discover [--project NAME]... [--apply] [--idle-timeout SECS]
                                                    # spawn Claude on .md files; without --apply writes to
                                                    # annotations-config.yaml.proposed for diff/review

cadence-memory list  [--kind K] [--project P] [--format json|table]
cadence-memory query <text> [--kind K] [--project P] [--limit N] [--format json|table]
cadence-memory get   <id>                           # raw markdown to stdout
cadence-memory show  <id>                           # metadata + body, formatted

cadence-memory ephemeral add <path> [--id ID] [--kind K] [--title T] [--tags ...] [--symlink]
cadence-memory ephemeral add --inline - --id ID …   # read note from stdin
cadence-memory ephemeral list   [--format json|table]
cadence-memory ephemeral remove <id>
cadence-memory ephemeral clear  [--yes]

cadence-memory chat [-- <args for claude>]          # sets CADENCE_MEMORY_DIR and launches Claude
```

The CLI auto-detects the active store: `--store` flag, then `CADENCE_MEMORY_DIR` env var, then walks up from `cwd` looking for a `config.yaml` next to `index.sqlite`.

## Typical bootstrap

```bash
cadence-memory init
# fill out projects[] in config.yaml by hand

cadence-memory discover                       # → annotations-config.yaml.proposed
diff annotations-config.yaml annotations-config.yaml.proposed
# fix things by hand, or rerun with --apply
cadence-memory discover --apply               # overwrites annotations-config.yaml
cadence-memory reindex
```

For a single project at a time:
```bash
cadence-memory discover --project billing --apply
cadence-memory reindex
```

## Document IDs

Stable, human-readable:
```
billing:README.md            # project document
:workflows/deploy-process.md # global document (lives in the memory dir itself)
eph:JIRA-1234                # ephemeral note
```

Use full IDs in `related`. Aliases are deferred (design §13).

## Requirements

- Python **3.14+**
- [Claude Code](https://docs.anthropic.com/en/docs/claude-code) on `PATH` (only needed for `discover` / `chat`)
- A `cadence-memory` directory that is itself a git repository

## Development

```bash
make install     # pdm install --dev
make test        # pytest tests/ -v
make test-cov    # with coverage
make lint        # ruff check
make typecheck   # mypy --strict
make check       # lint + typecheck + test
```

Conventions:
- Python 3.14+, `mypy --strict`.
- `Protocol`-based interfaces for every external dependency (`Store`, `ConfigLoader`, `FrontmatterParser`, `ClaudeRunner`) — tests mock these directly, never the real Claude CLI, real SQLite I/O across modules, or real git repos.
- Embedded defaults (`config.yaml`, `annotations-config.yaml`, `prompts/`, `skills/`) live under `src/cadence_memory/defaults/` and are read via `importlib.resources`.

Implementation tasks live under `cdc-tasks/` as `init` files, executed in order via cadence.
